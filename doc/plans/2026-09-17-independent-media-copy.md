# 媒体节点独立文件复制

## 范围与决策

用户确认：复制媒体节点时生成独立文件，不继续共享原节点文件。覆盖拖拽复制、同项目与跨项目粘贴、整组粘贴、图片笔记及分镜格媒体。导演台继续使用专用快照插入生命周期，不改变其私有运行资源。

采用先准备文件、后一次性插入节点的方式：复制中提示等待；失败不插入共享副本，保留原节点，可重新操作。空节点和文字节点保持即时插入。复用原生文件传输，不引入依赖。

## 已实现边界

- `nodeMediaCopy.ts` 串行分配和复制文件；不按内容去重。新文件清除原资产身份，保留模型、提示词、比例及参考关系。
- 图片、视频、音频、独立封面和分镜格分别复制；远程及内嵌媒体在桌面环境先落盘。纯 Web 环境无本地目录，不声称产生实体文件。
- Store 插入前检查 canvas derivation guard；拖拽复制还校验源数据未被重新生成替换。部分失败或过期结果只将本次文件送入可恢复回收流程；回收不可用时留在磁盘，不删除原件。
- 复制源在运行期间锁定，分组归档暂缓处理该文件；复制完成后由自动保存继续归档。
- 分组归档采用“准备目标文件 → 数据库事务迁移引用 → 同步内存并保存项目 → 清理旧文件”的移动流程；旧共享节点先按所有者拆分，最后一个引用迁移后清理源文件。复制节点仍产生独立实体文件。
- 入组、解组和分组改名同步迁移节点、生成历史、撤销记录、剪贴板及资产索引引用；只删除已搬空的目录。拒绝与其他分组冲突的目录名称，整组粘贴分配新的分组名。
- `indexedDb/mediaRelocations.ts` 在现有 metadata 表记录路径映射和待清理任务；事务或保存失败时保留源文件，下次归档恢复。后续项目、历史、消息、资产、角色、任务及剪辑工程写入应用映射，防止异步旧快照复活旧路径。路径映射持续保留，无 schema 升级。
- 清理只限项目内普通文件，拒绝路径越界、符号链接、大小或修改时间异常；目录只非递归删除。旧版本已经遗留且无法确定来源的重复文件不按名称或缩略图自动删除。仍含历史文件或其他内容的目录保留。
- 项目媒体生成、复制和分组归档的磁盘文件名附加独立随机身份，反复移动时替换已有身份后缀，避免名字不断增长；画布标题保持不变。查重异常必须停止。二进制写入使用排他创建，原生传输发布目标时拒绝覆盖已有文件；分组复制复用原生流式传输。系统另存为仍遵循用户在保存对话框中的选择。

回归入口：`tests/services/nodeMediaCopy.test.ts`、`tests/services/groupFileCopy.test.ts`、`tests/store/clipboard.test.ts`、`tests/store/groupFolders.test.ts`、`tests/store/history.test.ts`。覆盖独立文件分配、失败回收、项目切换、生成结果更新、共享分镜格、两图同组、跨组及撤销重做。

画布工具、笔记工具及模型请求回归一并通过；共 100 项相关测试分批通过，应用类型、测试类型、定向 ESLint、差异与 UTF-8 检查通过。Windows 打包端真实拖拽、大视频复制、磁盘满及用户原项目复测仍需实机验收；不将内存文件系统测试视为真实磁盘测试。

本次分组移动修正：13 个测试文件共 170 项通过；最终共享资产身份与事务终态调整后，相关 29 项再次通过。应用类型、测试类型、定向 ESLint、差异与严格 UTF-8 检查通过。实机原项目仍待复测，不自动删除旧版无法识别来源的重复文件。

## 回滚边界

无持久化 schema 变更；已复制文件是正常项目媒体。回滚代码不删除这些文件，也不合并已独立的文件；旧项目共享文件止损不能直接撤掉。
